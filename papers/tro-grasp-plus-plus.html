02输入张量与三个编码分支

物体与环境：同类结构，分别预训练、分别冻结

两路都使用 PointNet++ 形式的 VQ-VAE 编码器。物体专注可接触的形状；环境提供桌面、箱壁和其他物体的上下文。它们没有合成一个无法区分“目标”和“障碍”的点集，也不共享同一份编码器权重。

物体 512 点 / 环境 2048 点 → SA1：256 中心，半径 0.2，邻域 32，MLP [64,64,128] → SA2：128 中心，半径 0.4，邻域 64，MLP [128,128,256] → SA3：25 中心，半径 0.8，邻域 64，MLP [256,256,512] → 1×1 Conv：512 → 128 → VQ：2048 个 128 维码字 → 每个 patch：中心坐标 3 + 几何特征 128 = 131 维

半径属于归一化点云空间。当前实现先分别归一化两路点云用于几何编码，再将物体 patch 中心还原、变换到环境的归一化坐标系。因而几何编码坐标与构图坐标不能混为一谈；详见读者注。

连杆：除了长什么样，还要知道它是哪个部位

食指和中指的两根指节可能外形几乎相同，但在手掌上的位置、父子关节和活动范围不同。仅靠 BPS 外形，模型容易给它们预测相近甚至重叠的目标。++ 给网络补上区分这些连杆的结构特征。

非直接相连的连杆对在预计算关节样本中填零，但 RR 消息传递仍覆盖连杆对，不是只在 URDF 树的相邻节点上传递。由于带偏置的编码器会处理这些零输入，也不应把“输入填零”理解成“编码后严格为零”。

各字段分别投影，再相加。原始 131 / 262 / 134 维不是直接作为注意力头的通道数。这里的“6 维位姿”是 3 维平移和 3 维轴角；与某些论文所说的“6D rotation representation”不是同一概念。

03拆开一层：OR → ER → RR

每层也更新三类边的隐特征：对上一层边张量沿两个节点轴分别求均值，再平均，和当前 Value 一起输入 EdgeUpdateNet。最后一层不再更新边，因为后面只读取机器人节点。

要区分两个循环：单次去噪内部的 8 层学习更新隐特征；DDIM 的相邻采样步根据更新后的位姿重新计算实际几何关系。网络并不在每一层都把隐特征还原成新坐标。

相较原版，还有这些实现变化

  • 注意力实现：改用 PyTorch scaled_dot_product_attention；配置里的 c_atten_head=12 现在就是 12 个头。原版该变量 32 在 reshape 中代表每组通道数，384/32=12 组，不能直接比较变量值。
  • Value 和时间绑定：先分别线性映射再相加，避免显式复制后拼接大张量；在线性层层面可与拼接投影对应，不是凭空新增一种注意力理论。
  • 节点更新：当前 ++ 层中未保留原版那条“连杆全局 max pooling 后再拼接”的融合支路；RR 本身继续交换整手信息。
  • 边更新：OR、ER、RR 各有独立输出模块，当前 RR 分支确实调用 rr_edge_out。

两个输出头，怎样从 768 维得到 6 维噪声？

初始节点特征 + 8 层机器人节点输出 → 拼接 9 × 768 = 6912 → Linear → 768 平移头：拼当前平移 3 → 771 → 512 → 256 → 128 拼输入及各隐藏层：771+512+256+128 = 1667 → Linear → 3 旋转头：拼当前轴角 3 → 同样结构 → 3 每个隐藏层：Linear → LayerNorm → LeakyReLU 最终：L × 6 噪声预测；不是直接输出关节角

05训练、生成、IK 各负责什么

训练：恢复被加噪的连杆位姿

物体、环境与手结构作为条件，只给连杆平移和旋转加噪。当前训练配置为 1000 个 cosine 扩散时间步，每批采 5 个噪声时间；两路有效连杆噪声 MSE 相加。

附录给出 AdamW、学习率 10⁻⁴、1000 步 warmup、梯度裁剪 1.0、每 GPU batch 48、8 张 A100 80GB、bfloat16。数据与模型同时扩大，不能把总体提升全归因于新增 ER。

推理：20 次调用同一个网络

从高斯随机连杆位姿出发。每步预测噪声、估计干净位姿，再进行 DDIM 更新；节点中的几何和身份条件保持，几何边随位姿重算。

最后把位置恢复到实际尺度，使用 Pyroki 进行逆运动学。附录给出 8 个并行初值，再选 FK 后平均目标连杆位置误差最低者；这一步不等于完整的机械臂避障轨迹规划。

06为什么对杂乱场景更有帮助？证据有多强？

机制解释：若只观察同一个杯子，模型很难知道杯子左侧紧挨箱壁。ER 分支把箱壁相对每根手指的位置加入条件；位置 / 关节指纹则帮助区分外形相似的手指。前者补充“周围空间”，后者补充“手的身份”。这两件事与图像遮挡恢复不是同一个任务。

  • 杂乱不等于遮挡全解决。单视角部分点云实验另外生成训练数据并微调。基础模型的多视角结果不能直接当成强遮挡单视角的零样本结果。
  • 零样本手型结论有限。附录主要改变已知手的连杆长度与关节范围；它不能证明对任意全新拓扑、任意 URDF 都同样有效。
  • 条件学习不是硬约束求解。生成结果可能不完全可达、接触不稳或碰撞；噪声损失并未给出可执行性的数学保证。
  • 数据生成会影响结论。杂乱场景围绕可行抓取构建，并在手—物体投影占据区外放障碍。这个分布与完全任意堆叠的真实场景有差别。

07读者核对：不要把论文与代码拼成一个不存在的模型

以下是对提交 d0a00d050723 的静态核对，不代表对作者实验的复现或错误归因。

位置指纹：论文采样描述，代码 q=0 预计算

论文描述在可行关节空间采样并编码 link pose。仓库的 get_pos_embeddings 使用零关节向量做 FK；LinkPosEncoder 是逐连杆 MLP，没有对多个随机配置进行集合池化。关节关系分支则确实处理 128 个采样值，但它们是沿范围等距取值。

归一化：共享构图坐标，不等于共享编码前处理

论文文字说以环境中心和尺度归一化两路点云。代码给每个编码器分别归一化输入，再只将物体 patch 中心转换到环境归一化空间。因此不能说物体 VQ 编码器直接吃环境尺度下的点云。

连杆上限与手型列表随配置变化

论文与八手 val.yaml 使用上限 25；当前 train.yaml 使用 26，并包含 Wuji 相关元数据。论文的八手设置与后来扩展的九手资产应分开描述，不应自动把它们的数字合并。

DDIM 参数：要看推理配置和实际更新公式

论文附录与 val.yaml 都写 20 步、η=1；验证配置另有 λ=0.2，用于缩放随机噪声项。训练 YAML 的 η=0、λ=0 不能替代测试配方；代码并非只由一个 η 数值完整决定噪声注入。

训练损失：公式范数与代码平方误差

论文式 (8) 显示 L2 范数，没有平方；代码对平移 / 旋转分别计算平方误差并按有效连杆归一化。网络内部注意力没有传入有效节点 mask，但训练损失使用 mask；不能把损失遮罩当成注意力遮罩。

关节边双向写入，以及未调用的碰撞投影函数

预处理把同一个关节特征样本赋给正反两个索引；它是关系指纹，不能把反向项当成已经取逆的严格相对变换。project_pose_with_env_pc 虽然在文件中定义，检查的 DDIM 推理循环没有调用它；因此本页没有把“每步碰撞梯度投影”画成默认采样流程。
