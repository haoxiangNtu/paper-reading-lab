02 / INSIDE THE REFINER

把“看起来不对”变成 ΔR 和 Δt。

官方 RefineNet 实现

R′ = Rot(Δr) · R
t′ = t + Δt

旋转与平移分开更新；Δr 为旋转向量／轴角参数，不是直接相加的欧拉角。

04 / TRADE-OFFS

WAPR 更擅长什么，又不能替你解决什么？

研究结果 + 工程推断，分别标注

＋ 值得采用的理由

  • 少量候选也能工作

    大角度精化放宽了对初值的要求，为降低渲染和精化工作量创造条件。实际耗时仍取决于批处理、检测器与设备。

  • 快档与精度档都有公开结果

    BOP 有多个 WAPR 配置的提交；它不是只靠个别演示视频证明效果。

  • 能处理较大的帧间运动

    从更远初值恢复的能力，对低帧率或快速运动有潜在帮助；作者也提供了序列演示，但不足以推出所有跟踪场景领先。

  • 当前仓库支持批量推理与框输入

    可选 mask／box、GPU 加速和多实例批处理，便于系统集成。可运行性不等于在你的设备上已达标。

− 必须接受的边界

  • 几何和深度仍是前提

    错误尺度、缺失深度、mesh 与实物不符都会影响对齐。透明／强反光物体可能破坏深度输入，这是输入依赖带来的工程风险。

  • 仍是迭代估计，不是一次前向就结束

    重渲染、精化、评分仍有成本。多检测器高精度配置并不实时。

  • 对称性没有被“破解”

    没有可区分的纹理或几何时，多个方向可能同样正确；任务需要接受等价姿态，或引入额外观测。

  • 跟丢恢复是系统能力

    长时间完全遮挡、离开视野后重现，需要检测丢失、重检测和重新初始化；更大精化范围不能代替这些模块。

  • 版本与复现要谨慎

    论文、BOP 提交与当前默认配方不同；不能把某个配置的最高分、另一个配置的最快速度拼在一起。

能力与输入边界：WAPR 当前文档。透明反光深度风险、错误模型风险与恢复流程需求为基于输入／架构的工程分析，不是本文重新测得的性能结论。

06 / TWO IMPORTANT DISTINCTIONS

两个容易混淆的地方。

首次定位与视频跟踪，不是同一条计算路径。

FoundationPose 的 register 从全局候选出发，并调用评分器；track_one 以上一帧位姿为起点调用精化器，不再执行同样的全局候选搜索。因此，单帧定位榜单中的几十秒不能拿来描述它的常规跟踪速度。代码依据 ↗

上一帧位姿 → 当前帧裁剪／渲染 → Refiner → 当前帧位姿 ↺
Model-free 也可能先构建一个物体模型。

FoundationPose 无 CAD 模式使用带位姿的参考 RGB-D 视图学习物体 SDF 和外观，再提取可渲染 mesh；位姿网络本身无需为新物体微调，但物体表示仍需准备。WAPR 核心推理要求 metric mesh，外部重建可以提供它，重建本身不是 WAPR refiner 的输出。FoundationPose §3.2 ↗
